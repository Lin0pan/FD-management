# 2. Architecture constraints

_Last reviewed: 2026-08-07_

What is fixed regardless of preference. Choices that were ours to make live in
[chapter 4](04-solution-strategy.md) and [chapter 9](09-architectural-decisions.md).

## Organisational and business

| Constraint                                                                       | Rationale                                                              | Impact on design                                                                                                                                                                                                     | Source                                                                                                   |
| -------------------------------------------------------------------------------- | ---------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------- |
| FD has **no IT staff** and no budget for operations                              | A charity                                                              | Nothing may require administration: no database server, no scheduled jobs, no certificate renewals. Backup must be "copy this file" — [ADR-002](adr/002-store-the-register-in-a-single-sqlite-file.md)               | FD, asked directly — [ADR-002](adr/002-store-the-register-in-a-single-sqlite-file.md)                    |
| **One developer**, part-time, and the system must survive a handover             | Reality of the project                                                 | Legibility beats cleverness; no pattern heavier than the problem needs — no events, no CQRS, no aggregates                                                                                                           | `CLAUDE.md`                                                                                              |
| **A few hundred households (~250), a handful of users, one distribution a week** | FD's actual size — the household count moves and is not a design input | Volume never justifies a design choice. A whole-register read is acceptable where it makes a rule clearer                                                                                                            | `docs/archiv/domain_analysis.md`                                                                         |
| **Five-year-plus horizon** with little maintenance                               | FD cannot fund continuous upkeep                                       | No release-candidate dependencies; the fastest-moving one is pinned and quarantined — [ADR-004](adr/004-pin-the-next-js-major-and-keep-the-core-outside-the-framework.md)                                            | FD, asked directly — [ADR-004](adr/004-pin-the-next-js-major-and-keep-the-core-outside-the-framework.md) |
| **Staff decide, the software does not**                                          | Eligibility and escalation are human judgements FD makes case by case  | No thresholds anywhere: reminders, no-shows and card losses are _counted_ and never acted on automatically                                                                                                           | `docs/archiv/domain_analysis.md` §4.2                                                                    |
| **FD has ruled out login**                                                       | A handful of trusted colleagues at one counter                         | No actor anywhere in the system, including the audit log — [ADR-003](adr/003-ship-without-login-and-bind-the-application-to-localhost.md), [ADR-006](adr/006-record-what-when-and-why-in-the-audit-log-never-who.md) | FD, asked directly — [ADR-003](adr/003-ship-without-login-and-bind-the-application-to-localhost.md)      |

## Regulatory

| Constraint                                                             | Rationale                                                                  | Impact on design                                                                                    | Source                                                                                              |
| ---------------------------------------------------------------------- | -------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------- |
| The register holds **sensitive personal data about vulnerable people** | Names, addresses, birthdates and proof of need of people using a food bank | Local-first: no cloud, no third-party service, no telemetry. The app binds to localhost only        | FD, asked directly — [ADR-003](adr/003-ship-without-login-and-bind-the-application-to-localhost.md) |
| **Synthetic test data only**                                           | The same                                                                   | Fixtures and the demo seed use Faker; no real name, address or certificate may enter the repository | `CLAUDE.md` §Testing                                                                                |

## Technical

| Constraint                                                                                | Rationale                                          | Impact on design                                                                                                                                                               | Source                                   |
| ----------------------------------------------------------------------------------------- | -------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ---------------------------------------- |
| **Node 22**, pinned by `.nvmrc` and `engines`                                             | One runtime FD's machine and CI agree on           | CI reads `node-version-file: .nvmrc`; no feature newer than that runtime                                                                                                       | `package.json`, `.nvmrc`                 |
| **TypeScript strict**, no `any`, no non-null `!`                                          | The type system is the cheapest test there is      | Narrow or fail loudly; illegal states are made unrepresentable rather than validated                                                                                           | `tsconfig.json`, `CLAUDE.md`             |
| **SQLite has no decimal type**                                                            | The datastore                                      | All money is `Int` cents; `Float` and `Decimal` appear nowhere in the schema                                                                                                   | `prisma/schema.prisma`                   |
| **SQLite has no enum type**                                                               | The datastore                                      | Groups, statuses, colours and card reasons are strings the domain validates on the way in _and_ out                                                                            | `prisma/schema.prisma`                   |
| **SQLite cannot fold umlauts or Unicode case in `WHERE`, and has no timezone arithmetic** | The datastore                                      | Two derived values must be stored as keys — the folded names and `dayKey` — with an argument each, see [ADR-007](adr/007-derive-anything-computable-rather-than-storing-it.md) | `prisma/schema.prisma`                   |
| **Prisma cannot express a partial unique index**                                          | Tool limitation                                    | The slot rule's index is hand-written at the end of the init migration, and is dropped by every regeneration                                                                   | `prisma/migrations/*_init/migration.sql` |
| **Runs on one machine, offline-capable**                                                  | The hall has FD's laptop and sometimes no internet | No runtime network dependency: the font is self-hosted, nothing is fetched from a CDN                                                                                          | `src/app/layout.tsx`                     |

## Conventions (binding, enforced)

| Constraint                                                               | Rationale                                                                                       | Impact on design                                                                                                                   | Source                                          |
| ------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------- |
| **Dependencies point inwards only**: `app → application → domain`        | See [ADR-001](adr/001-layer-the-system-hexagonal-lite-and-enforce-the-boundary-in-the-build.md) | `fd/domain-boundary` and `fd/application-boundary` in ESLint; a violation fails `npm run lint` and CI. No inline disables          | `eslint.config.mjs`, `src/architecture.test.ts` |
| **Time is injected**                                                     | Time-dependent rules must be testable                                                           | A zero-argument `new Date()` or `Date.now()` is a lint error outside `infrastructure/`; the wall clock is read in exactly one file | `src/infrastructure/clock.ts`                   |
| **100 % coverage on `domain/` and `application/`**                       | A consequence of TDD on pure logic, not a number chased elsewhere                               | The gate is in `vitest.config.ts` and blocks CI; coverage is deliberately _not_ collected on UI or infrastructure                  | `vitest.config.ts`                              |
| **Identifiers English, UI strings German**, and only in `src/i18n/de.ts` | The team reads English code and FD reads German screens                                         | No German literal may appear in a component                                                                                        | `CLAUDE.md`, `src/i18n/de.ts`                   |
| **Typed domain errors only**                                             | The UI decides its tone from the error's code, never from its sentence                          | No bare `throw new Error("…")`; `DomainErrorCode` is a closed union                                                                | `src/domain/errors.ts`                          |
| **No `onDelete: Cascade` anywhere**                                      | See [ADR-010](adr/010-never-hard-delete-a-record-archive-and-let-the-database-refuse.md)        | `src/infrastructure/prisma/schema.test.ts` fails if one reappears                                                                  | `prisma/schema.prisma`                          |
| **`main` is ruleset-protected**; conventional commits; green before push | Everything lands through a PR with CI green                                                     | Husky runs lint-staged pre-commit and the unit suite pre-push                                                                      | `CONTRIBUTING.md`, `.husky/`                    |
