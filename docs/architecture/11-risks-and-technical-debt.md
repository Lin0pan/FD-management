# 11. Risks and technical debt

_Last reviewed: 2026-08-29_

A **risk** might happen and is managed by mitigation and monitoring. **Debt** is a shortcut already
taken, paid for in every future change. Owner is "the maintainer" throughout, because there is one —
which is itself the third risk below.

## Risks

If that day passes unnoticed, the next regeneration destroys real data                                                                                                                                                                                | Total loss of live data                                                                 | Medium — the trigger is an event nobody is watching for | Make the reversal part of the go-live checklist, not a rule to remember. Early warning: any `prisma migrate dev --name init` after go-live                                                                                                                                                       | The maintainer      |
| **The hand-written partial unique index is dropped by every migration regeneration.** Without it, the one-household-per-number rule rests on application code alone                                                                                                                                                                                                                                                                               | Two households on one customer number; the quota stops meaning anything                 | Medium while pre-release regeneration is normal         | `src/infrastructure/prisma/schema.test.ts` greps the generated SQL. That test is the early warning and must never be weakened                                                                                                                                                                    | The maintainer      |
| **The Excel migration is unanswered.** Import script or re-key a few hundred households by hand — undecided                                                                                                                                                                                                                                                                                                                                       | Blocks go-live; a hand re-key is days of work and a fresh source of typos               | Certain to be faced                                     | Decide before scheduling go-live. Note it also decides _when_ the ADR-009 switch flips                                                                                                                                                                                                           | DF + the maintainer |
| **Single-developer key-person risk.** One person holds the design in their head                                                                                                                                                                                                                                                                                                                                                                   | A handover without these documents would be expensive; with them it is merely hard      | Certain over a five-year horizon                        | This documentation set is the mitigation. Keeping it true is the ongoing cost — see the README's "keeping it current" note                                                                                                                                                                       | The maintainer      |
| **A shared, possibly unlocked machine is the entire access control.** [ADR-003](adr/003-ship-without-login-and-bind-the-application-to-localhost.md) accepts this consciously                                                                                                                                                                                                                                                                     | Anyone with physical access reads or edits the register                                 | Depends entirely on DF's practice                       | Screen lock and machine placement — an operational control, not a software one. Revisit the ADR if DF ever wants the register on a second machine                                                                                                                                                | DF                  |
| **The pinned Next.js major goes stale.** [ADR-004](adr/004-pin-the-next-js-major-and-keep-the-core-outside-the-framework.md) buys stability at the price of a growing jump                                                                                                                                                                                                                                                                        | An eventual upgrade touching `src/app/` wholesale, or running on an unsupported version | Certain, on a multi-year timescale                      | The layering means the blast radius is `src/app/` only. Early warning: the pinned major leaving security support                                                                                                                                                                                 | The maintainer      |
| **The pinned Node 26 is a _Current_ release until 2026-10-28**, not LTS. [ADR-011](adr/011-track-the-newest-even-numbered-node-release.md) took this on deliberately to buy the longer runway                                                                                                                                                                                                                                                     | Semver-major changes can still land in the line; no LTS support guarantee until then    | Certain, and self-resolving on that date                | Bounded by the calendar and by DF holding no real data before go-live. | **Safari is gated by WebKit, which is not Safari.** Playwright's engine has no Apple shell, so anything Apple wraps around it is never exercised. **Realised once already** — the first manual pass found the native date input entering the wrong day, which [ADR-013](adr/013-type-calendar-days-as-tt-mm-jjjj-instead-of-using-the-native-date-input.md) removed. Early warning: a DF report that no spec reproduces — which is exactly how ADR-013 started | The maintainer      |

## Review cadence

This chapter is worth nothing if it is written once. Re-read it whenever an ADR is added, and in full
before go-live — at which point the backup risk and the migration-switch risk stop being risks and
become either resolved or realised.
