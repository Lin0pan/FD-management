## Codebase Patterns
- The page at /kunden/[id] already exists (built in US-01 as the card landing). It renders
  `CustomerCardView` from `readCustomer` and links to the card view at /kunden/[id]/karte. Extend it
  rather than creating a new page.
- Derive-don't-store: age is a pure domain fn `ageInYears(birthDate, today)` in
  `src/domain/customer/householdComposition.ts`, sharing the anniversary/§188 BGB rollover convention
  with `composition`/`grownUpFrom` (29 Feb → 1 Mar in non-leap years). The application layer
  (`read-customer.ts`) derives ages via `deps.clock.now()` and hands them to the page ready to render.
- `RegisteredCustomer.reminderCount` already lives on the customer entity — the page reads
  `view.customer.reminderCount` directly, no application change needed.
- German UI strings only in `src/i18n/de.ts`. Inflected forms (e.g. "1 Jahr" vs "N Jahre") are
  functions in the dictionary, never in components.
- Coverage is gated at 100% on domain/ and application/. Any new branch needs a named boundary test.
- e2e specs (tests/e2e/*.spec.ts) are not run by `npm run test:coverage`; run `npm run test:e2e`
  separately. Existing registration.spec asserts household-member *count*, not text, so a rendered
  age suffix is safe.

## 2026-07-25 - US-002 (Customer status transition state machine)
- Added `src/domain/customer/status.ts`: `transition(from, to, reason?)` returning the target for the
  four allowed moves (ACTIVE→BLOCKED, BLOCKED→ACTIVE, ACTIVE→ARCHIVED, BLOCKED→ARCHIVED) and throwing
  otherwise. `Status` is a type alias of the existing `CustomerStatus` from customer.ts — single
  source of truth, not a second enum.
- New typed `IllegalStatusTransition` error in errors.ts (carries `from`/`to`) for any move out of
  ARCHIVED and every no-op. A reason-less `→ BLOCKED` reuses the existing
  `MissingAuditReason("customer.blocked")`, not a new class (per PRD §US-08.1).
- Tests cover all 9 ordered pairs plus the empty/whitespace/undefined-reason branches.
- Files changed: src/domain/customer/status.ts (+test), src/domain/errors.ts.
- Checks: lint, typecheck, test:coverage (491 tests, 100% on pure layers), build all green.
- **Learnings for future iterations:**
  - `CustomerStatus` and `parseCustomerStatus` already live in `customer.ts`; don't redefine the enum
    in status.ts — alias it. US-004 will need the `blockReason` Prisma field + invariant, and US-003
    the blockCustomer/unblockCustomer use cases that call `transition`.
  - Adding a domain error = add the string to the `DomainErrorCode` union AND the class; coverage on
    errors.ts is gated at 100%, so every new error must be exercised by a test (status.test.ts does).
