## Codebase Patterns
- **Measuring a screen's height**: `next build` then `npm run start -- --port 3100` (kill any
  next-server first), then playwright-cli. `document.body.scrollHeight` is useless on a short page —
  the shell fills the viewport, so it reads 900 either way. Measure the **last `main > *` child's
  `getBoundingClientRect().bottom`**, and measure a *populated* screen too (`/ausgabe?nummer=1`).
- **playwright-cli in this sandbox**: `playwright-cli open` only — `--browser=chrome` fails, there is
  no Google Chrome at /opt/google/chrome. The skill-version warning banner is noise; ignore it. Use
  `--raw` and `tail -1` to get just the value out of `eval`.
- **A grep across `tests/` is part of removing a UI element**, not only `src/`. A spec in a
  *different* file, named after a different screen, can be the one driving the element you are
  removing.
- **The dev server on 3100 reads `data/fd.db`**; the e2e servers read `data/e2e.db` (3000) and
  `data/e2e-isolated.db` (3001). Playwright's config reuses an existing server outside CI, so kill
  any `next-server` before `npm run test:e2e` or the suite tests the previous build.
- **Never `pkill -f next-server` from the Bash tool** — the pattern matches the tool's own wrapper
  command line and kills the shell (exit 144, no output). `pgrep -f "port 3100" | xargs kill` does
  the same. Use `ps -eo pid,args | grep -E "next-serve[r]"` and `kill` the pid.
- **`getByRole("alert")` is never 0 in this app.** Next injects a client-side route announcer with
  `role="alert"` into every page — invisible in the SSR HTML, so `curl | grep` disagrees with
  Playwright. Assert the absence of an error with `page.locator('[data-slot="alert"]')`; every
  shadcn `ui/` primitive carries a `data-slot`.
- **`tsconfig.json` includes `tests/`**, so `npm run typecheck` type-checks the specs. Deleting a key
  from `src/i18n/de.ts` fails typecheck while any spec still reads it — the spec has to go first.
- **`docs/technical_documentation.md` documents the e2e suite test by test**, so changing a spec
  makes it stale and no gate can tell. Grep that file for the *spec file name* after touching a
  spec, and for the feature's vocabulary after removing a feature — it is 2,500 lines and describes
  the same thing from the layer's side, the screen's side and the suite's side.
- **`docs/technical_documentation.md` documents a domain module twice**: once as a line in the `src/`
  tree around line 156 and once as a `### <path>` section. Adding a module means both, or the tree
  lists a file the reference section never explains.
- **`playwright-cli eval` takes one expression.** Multi-statement JS fails inside `UtilityScript`;
  wrap it in an arrow IIFE — `"(() => { const x = …; return JSON.stringify(x); })()"` — and quote
  attribute selectors (`[data-testid=\"walk-hint\"]`).
- **A disabled control is skipped by Tab**, so tab traversal cannot prove DOM order at the ends of a
  row. Read the order with one `querySelectorAll` over the row's testids, and check the traversal on
  a state where every control is enabled.
- **A retracted requirement is struck through, marked and kept**, never deleted: `~~criterion~~`
  plus `[withdrawn]` and the reason, in both `docs/user_stories_mvp.md` and the story's PRD. Say
  what is *not* withdrawn too, or the next reader removes a parameter that still has callers.
- **An e2e fact about "the whole register" is read from Prisma at assertion time**, never
  hard-coded: the specs run serially in *alphabetical file order* against one shared `data/e2e.db`,
  so which number is the first or last of a group depends on which specs ran before yours. Seed a
  block for what you own; query for the ends.
- **`counter-customer-number` identifies a household at the counter, `counter-card-number` does
  not** — a household another spec reissued a card to shows `Nk2`, so an assertion on `Nk1` fails
  for reasons that have nothing to do with what is under test.
- **Adding a method to a port breaks five hand-written fakes.** `DistributionRecordRepository` is
  faked in `customers.test.ts`, `lookup-customer.test.ts`, `maintain-customer.test.ts`,
  `correct-attendance.test.ts` and `record-attendance.test.ts` — `grep -rln "<PortName>" src/ tests/`
  before touching `ports.ts`, because typecheck is where you find out otherwise.
- **Berlin and UTC only disagree between 23:00Z and midnight** (in winter; 22:00Z in summer). A test
  that means to prove "the Berlin day, not the UTC one" must put an instant *in that hour* — a
  23:30 **Berlin** time is 22:30Z and proves nothing, because both calendars still say the same day.
- **A `<details>` keeps `open` through a soft navigation, not only a re-render.** Following a
  `<Link>` on the same route re-renders in place, so a fold the user opened is still open on the new
  screen. `key={<what the page is about>}` on the component holding it remounts it closed. Only a
  browser check finds this.
- **A UI review needs a *populated* screen.** `data/fd.db` has ~20 households; a scroll cap or a
  column layout proves nothing against 8 rows. Copy the db to `/tmp`, seed through Prisma, and point
  `DATABASE_URL` **and** `FD_FIXED_NOW_FILE` at the copy for `npm run start -- --port 3100`.
- **E2E customer-number bands are taken, not squeezed into**: 201–206/239 (counter), 211 (portions),
  221–222 (serve), 231 (reminders), 241 (block), 251 (reissue), 271 (age 13), 281–285 (customer
  list), 291 (customer record), 311–315 (group walk). A new spec takes the next band up.
