## Codebase Patterns
- **A transaction cannot span two ports.** There is no unit of work in this codebase and
  `$transaction` appears only inside adapters, so an invariant across two tables owned by two
  repositories is kept by **ordering plus idempotence**, never by one SQL transaction. State which
  order and why on the port (US-35.2's `freezeSession` writes before the session is ended, and
  re-takes the freeze whole so a half-done sequence heals). The tempting alternative — one adapter
  stamping the other's column — hides the write where nobody looks for it.
- **Adding a method to a repository port breaks every hand-written fake at once**, and for
  `DistributionRecordRepository` that is eight test files. The house stub is
  `Promise.reject(new Error("… has a suite of its own"))`, not a no-op: a use case that starts
  calling the method then fails loudly in the suites that have no business exercising it. `tsc`
  names the files; patch them with a script that inserts before the class's first `\n}\n`.
- **Adding a `DomainErrorCode` is a three-file change**: the union in `src/domain/errors.ts`, the
  class beside it, and `TIERS` in `src/app/notice-tier.ts`. `TIERS` is a `Record` over the union, so
  the *build* fails until the code is tiered — that is the mechanism, not an obstacle. The header
  comment of `notice-tier.ts` counts the codes ("a 32nd code…", "the six red ones"), so it goes
  stale silently; update it with the entry.
- **The same mechanism guards `SettingsChange`**: its `switch` in `src/app/einstellungen/page.tsx`
  is exhaustive with no `default`, so adding a member to the union fails the build until the screen
  renders it. Do not silence it with a `default` branch.
- **An error class with no caller yet still needs a test**, because `domain/` coverage is gated at
  100%. `src/domain/errors.test.ts` is where those live — see the `MissingAuditReason` block for the
  shape, including the comment saying which story will call it.
- **`errors.ts` cannot import from `domain/card/`**: `cardNumber.ts` imports `errors.ts`, so a
  message that wants to read `66k1` writes the `k` inline rather than calling `formatCardNumber`.
- **Adding a field to `Settings` is a wide change before it is a deep one.** `createSettings` is
  called from the repository, the seed, the settings server action and every hand-written fake in
  the application tests; all of them must supply the new field before anything compiles. Land the
  field with a placeholder value at each call site, then replace them in the story that owns each.
  Get the *files* out of a wide break rather than the errors:
  `npm run typecheck 2>&1 | grep -E "^src/" | cut -d'(' -f1 | sort -u`.
- **A test that merely *uses* a field is not a test *of* it.** Several `settings.test.ts` cases
  reach for an arbitrary second field to prove the same-instant tie rule or the audit's changed-field
  list. When that field goes away, **re-point them**, do not delete them — deleting takes an
  unrelated rule with it and drops coverage below the gate.
- **A Prisma `P2002` cannot always name *which* constraint was broken.** `meta` is
  `{ modelName, target: [columns] }`, but where two unique indexes both cover the offending row
  SQLite reports only one of them, and not the one that was declared or created first. Where the
  distinction matters, match the target for the *shape* and then ask the database the question that
  actually distinguishes the two faults (`card-repository.ts`'s `issue` counts the customer's own
  rows on that index). For a **nested** write Prisma reports the *rooted* model — a card refused
  inside `customer.create` comes back as `modelName: "Customer"` — so the model name alone tells
  nothing about which table failed.
- **Regenerating `prisma/migrations/` drops the hand-written partial unique index** on
  `Customer.customerNumber` (`Customer_customerNumber_onRegister_key`) at the end of the migration
  SQL. `src/infrastructure/prisma/schema.test.ts` greps for it and for the `onDelete: Restrict`
  clauses, so a lost line fails CI rather than production — but re-add it deliberately. Three things
  batches 25–27 each had to learn:
  - **Delete `data/fd.db` before `migrate dev`**: with the old migration row still in
    `_prisma_migrations`, Prisma refuses to regenerate and writes nothing.
  - **Verify with `diff`, not by reading the new file**:
    `git show HEAD:prisma/migrations/<old>/migration.sql > /tmp/old.sql && diff /tmp/old.sql <new>`
    states in a few lines what the story is allowed to have changed. Anything else is a Prisma
    version drifting the DDL under you, which no gate would attribute to this commit.
  - **`migrate dev` applies the migration *before* the hand-written index is appended**, so the
    database it leaves does not have the index even though the committed SQL does. `npm run db:reset`
    afterwards is what makes the two agree — check with
    `SELECT sql FROM sqlite_master WHERE name='Customer_customerNumber_onRegister_key'` rather than
    trusting that the reset ran.
  - A regeneration **renames a directory that documents cite by name**. `grep -rn "<old-timestamp>_init"
    docs/ src/ tests/` afterwards; prefer the `prisma/migrations/*_init/migration.sql` glob, which
    survives the next one.
- **Never `pkill -f "next dev"`, and never `pkill -f "node.*next-server"`** — both patterns match the
  Bash tool's own wrapper command line and kill the shell (exit 144, no output). **And `ss` is not
  installed in this sandbox**, so `ss -ltnp | grep :3000 || echo free` reports "free" for every port,
  always: the `||` fires on `command not found`. (Batch 27's per-story notes recommend `ss` in two
  places — they are wrong; that is the bug this bullet exists to stop.) Check
  `ps aux | grep "[n]ext-server"` — the bracket keeps the pattern out of its own match — and
  `kill <pid>` by number.
- **A stale `next start` from an earlier iteration silently serves a mixed build.** The new
  `npm run start` fails with `EADDRINUSE` in the background while the page still renders, from the
  old server reading the *new* chunks off disk — a couple of console 500s are the only symptom.
  Check for a live server (`ps`, above) **before** trusting any browser check.
- **`npm run db:reset` does not reach a server that is already running.** It deletes `data/fd.db`,
  and SQLite keeps serving the running process from the deleted inode, so the screen goes on showing
  the pre-reset data. Restart the server after a reset, or the verification is of the old database.
  `db:seed` fills settings only — customers are not seeded, so a reset empties whatever manual
  clicking built up (the e2e suite makes its own registers).
- **Changing a seeded policy value moves e2e expectations.** `grep -rn ',00 €' tests/e2e/` before
  editing a number in `seed.ts`.

- **Choosing a number at the intake now starts with choosing the week.** `/kunden/neu` offers one
  parity at a time, so `selectOption("236")` finds no such option unless `#group-BLUE` is checked
  first — and the radio is controlled, so the check has to come after `hydrated()` or it moves the
  dot without moving the list. Same on the record's `number-change-select`. Six specs that used to
  open a `<details>` (`group-choice-open`, deleted in US-31.6) now just check the radio, and every

- **A spec that reads the session which ended LAST must run on the REAL clock.** `lastEnded` orders
  by `endedAt`, and the register holds sessions from every file before it: the ones that pin January
  are stamped January, but the ones that edit *settings* cannot pin at all — a saved version is
  recorded at the real now and is only in force there — so `price-cap.spec.ts` ends its afternoon at
  the real now and **beats** any pinned-past session. `session.spec.ts` therefore pins nothing,
  `rmSync`s the now-file in its `beforeAll`, and dates its fixtures from `new Date()` (the clock
  rule is `src/`-scoped, so a spec may read it). The trap is silent: the proposal assertion passed
  against another spec's RED afternoon before a summary assertion two tests later exposed it.
- **A spec that does not set the policy may not state a price.** With the real clock the version in
  force is whatever the files before it left (`price-cap.spec.ts` leaves 9,99 € a head, capped at
  5,00 €), so `session.spec.ts` reads the Betrag field and puts it through `parseEuros` — the very
  function the server action reads the form with — and asserts every later figure against *that*.
  A correction goes to **0,00 €**, the one amount that is certainly not an overpayment whatever the
  cap is.
- **Two specs share the isolated register now** (`ISOLATED_SPECS`), `number-group` before
  `waiting-list`. Sharing is safe only because each empties it with `clearRegister` in its own
  `beforeAll` and sets the quota it needs in its first test — which they both have to do anyway, since
  a CI retry replays a `serial` block against the register the previous attempt filled. A spec needs
  that register when it has to **decide the quota**: since US-31 that includes making one *week* full
  while the register is not, which no quota on the shared register could ever reach.
- **e2e spec files run in alphabetical path order, one worker, one shared database.** So a spec that
  *writes* shared state is only ever seen by the files sorting after it — `npx playwright test --list`
  prints the order, and a **rename moves a spec in that order** (batch 27's `portions.spec.ts` →
  `allowance.spec.ts` moved it from the middle to second). Anything a spec asserts as an **absolute
  count of a shared thing** is therefore a landmine: `settings.spec.ts` counted its version history
  as `3` and `4` and read the seeded version as `nth(2)`. It now takes a baseline with
  `versionCount(page)` and asserts `before + 1`, and reads the oldest version as `.last()` — the same
  claim, stated so that it does not depend on who ran first.
- **Two consecutive saves on the settings screen need a `page.reload()` between them in e2e.** A
  successful save *clears* the form, and the revalidated render that does it can land **after** the
  next `fill`, rewinding the field to the stored value; the second save then appends a version that
  changed nothing and every history index below it shifts. **`selectOption` loses the race too** —
  this bullet used to say it survived, and batch 29 watched WebKit fail the Ausgabetag spec on that
  claim twice in a row. Reload and re-assert the stored value before touching the field again,
  whichever control it is.
- **The customer record renders two different household blocks.** `/kunden/<active>` gives the live
  editor (`household-editor.tsx`), `/kunden/<archived>` gives `HouseholdReadOnly` in `[id]/page.tsx`.
  Both hold the same tiles, so a screen-level change has to be checked on one of each — **seed
  customer 6 is archived**.
- **Counts baked into prose go stale in files no story names, in both directions.** Removing two
  settings made "the ten fields of the settings form", "nine of the ten need no translation",
  "Seven of the nine settings", "printed only five of the eight settings" and a `toHaveLength(8)` all
  wrong at once; *adding* a field or a tile does the same. After any such change,
  `grep -rn "nine\|ten fields\|eight\|six tiles\|four figures" src/` — the suite catches only the
  assertion. The same applies to an **exported type you delete or rename**: `grep -rn "<TypeName>"`
  finds the `{@link}`-shaped references left behind in comments, which no gate sees.
- **Prettier does not reflow comments.** Shortening a sentence inside a `/** */` block leaves a
  ragged short line that `prettier --check` happily accepts — and so does an over-wide one, though
  the repo's width is 100. Re-wrap the paragraph by hand, and **measure with Python, not `awk`**: an
  em dash is three bytes, `awk` counts it as three columns, and every sentence carrying one is
  reported as a violation it is not.
  `git diff -U0 | python3 -c "import sys; [print(len(l[1:-1]), l) for l in sys.stdin if l.startswith('+') and not l.startswith('+++') and len(l[1:-1]) > 100]"`
- **A `toEqual` on a *whole* record is the assertion a new field breaks, and `tsc` cannot see it.**
  Adding a required field to a domain type (`IssuedCard.customerNumber`, batch 30) leaves every
  `expect(x).toEqual({ …every field… })` typechecking and failing at run time with a one-line diff.
  The compiler finds the *constructors*; only the suite finds the assertions. Same family as the
  „renaming a Prisma column is not finished when `tsc` is green" bullet — run the tests even when
  the wide break looks closed.
- **A domain story that changes a signature is not domain-only.** Deleting an exported function or
  giving one a second argument breaks `app/`, `application/` and `infrastructure/` in the same
  commit, and those call sites are that story's own work — the tree has to be green at every
  iteration. Two rules keep it honest: change the *shape* only and never the behaviour, and write in
  a comment which later story deletes the line. Where a narrowing is still needed for one more
  iteration because a column still holds the old value, push it *down* into the adapter rather than
  keeping the domain function alive (batch 31's `parseStoredGroup` in `card-repository.ts`).
- **A required field added to a type a *writer* passes is a signal to split the type**, not to teach
  every writer the new field. `NewCard = Omit<IssuedCard, "customerNumber">` and `NewCustomer.card:
  NewCard` kept the slot the store's to fill in — which is the actual invariant — and cut the fixture
  break from ~50 errors to 17 as a side effect. `RegisteredCustomer extends NewCustomer` then
  re-declares `card: IssuedCard`, which TypeScript allows because the stored shape is assignable to
  the written one. Look for that split whenever a "wide break" is mostly test fixtures: it usually
  means the field belongs to the read model alone.
- **Prettier owns every markdown table in `docs/`, and `npm run lint` does not check it.** `lint` is
  `eslint` alone; markdown formatting is `npm run format:check` (the pre-commit hook runs it). Widen
  one cell and Prettier re-flows every row of that table, so run `npx prettier --write` on the files
  you touched *before* reading the diff — otherwise you are reviewing a re-alignment.

- **An unreachable `?? fallback` fails the 100% branch gate.** Where a lookup cannot miss (a row that

  answer that went nullable and one caller not ready for it — **move the expression to where a test

  states it, and names which bullets it answers when it follows several. The per-story PRDs in
  `tasks/` are the same kind of record: they say what was asked for, so a superseded one gets a

- **A controlled field filled straight after a `goto` needs `fillSticky`, not `fill`** — including a
  `<textarea>`. Hydration re-renders it from the prop and the typed text comes back with the stored
  value spliced into it (`notes-field`, batch 29), which reads like a broken assertion rather than a
  race. `tests/e2e/day.ts` explains the window; the rule is the whole of it: plain `fill` only once
  the page has been interacted with, or on a field React does not own.
- **Before touching an e2e spec your story has no business in, `git stash` and run the suite on
  clean `HEAD`.** It is the only thing that separates a regression from this suite's WebKit
  flakiness. Note that a failure **aborts the files behind it** (`6 did not run`), so one flake hides
  whatever else would have failed — and a green run after a fix is worth repeating twice.
- **A controlled *radio* does not survive React's post-action `form.reset()`; a controlled text input
  does.** React keeps a controlled input's `defaultValue` attribute in step with its value and does
  **not** do the same for `defaultChecked`, so a reset restores the radio from the attribute the
  *server* rendered while the unchanged `checked` prop makes React repaint nothing — the dot rewinds
  and the state it is supposed to show does not. One line fixes it, on the input itself:
  `ref={(node) => { if (node !== null) node.defaultChecked = <the state>; }}`. Passing `checked` and
  `defaultChecked` together instead is a React warning, not a fix. No gate sees any of this: it is a
  browser check or nothing (batch 31, `/kunden/neu` and the record's number control). Assert
  `hasAttribute("checked")` and not only `.checked` — the attribute is what the reset restores from,
  so it is the half that tells a fixed control from one that happens to look right.
- **`germanDate` is for days and `germanDateTime` for instants, and the difference is the time zone.**
  `germanDate` reads UTC deliberately (a stored day is midnight UTC), so passing it a *moment* names
  the wrong day for anything after 23:00 UTC — and a session left running overnight is exactly the
  case the last-session summary is read in. Both instants of an afternoon are written out in full
  rather than as one day with two times, for the same reason: „14:00–08:30" would state an overnight
  session as a morning.
- **`list[0]` lies in this repo; `list.at(0) ?? fallback` does not.** `tsconfig` has no
  `noUncheckedIndexedAccess`, so an index access on a possibly-empty array types as present and the
  `?? fallback` beside it reads as dead code to the next reader. `.at(0)` returns `T | undefined`,
  which lets a chain of `??` state the fallbacks a value actually has without a `!` — see
  `number-control.tsx`'s pick → own slot → group's lowest.
- **Radios that must not be submitted simply have no `name`.** An unnamed control is left out of
  `FormData`, mutual exclusion comes from React's `checked`, and what is lost is only the arrow-key
  roving of a native group — Tab reaches each radio and Space picks it. That is how a control can be
  browser state inside a `<form>` without a field nobody reads (US-31.6).
- **A `<select>` or a text input inside a form on a *record* screen needs `onKeyDown={guardEnter}`.**
  `submitsOnEnter` (`src/app/enter-guard.ts`) returns `true` for `SELECT`, so Enter in a dropdown
  submits the form around it — and where the save sits inside a `<details>` confirmation, that
  keystroke performs the write with the sentence describing it never having been on screen. No gate
  sees this: typecheck, lint and the unit suite are all green either way. Press Enter in the control
  in a browser. (`group-control.tsx`'s radios have the same exposure and no guard.)
- **The two-step save has one shape in this repo, and it is `reissue-controls.tsx`'s**: a `<summary>`
  wearing `buttonVariants({ variant: "outline" })` plus `list-none
  [&::-webkit-details-marker]:hidden`, then an `<Alert>` naming what will happen and the real
  `<Button type="submit">` inside the same `<details>`. It tabs select → summary → submit and reads
  as `group > generic + alert + button` in the accessibility tree. Copy it; do not invent a second.
- **`npm run db:demo` is what makes a record worth driving in the browser.** `db:reset` seeds
  settings only, so every `/kunden/<id>` is a 404 and „the screen is broken" is the wrong conclusion.
  In the demo register ids 1–5 are ARCHIVED, 6/9/10 ACTIVE, 7/8 BLOCKED — **id 6 is the active record
  and id 1 the archived one**. (The „seed customer 6 is archived" bullet elsewhere is about
  `seed.ts`, a different register.) Slots 1 and 2 are held by re-registrations, so the free pool
  starts at 3.
- **Verify a screen's acceptance list with one `--raw eval` returning `JSON.stringify({...})` over
  its testids**, rather than a snapshot per claim: a receipt, the revalidated facts above it, a
  control's post-save value and a collapsed disclosure come back in one call for a fraction of the

### Where batch 35 starts

US-34 made a hand-out belong to a **session** (ADR-020). DF then asked for something the software
has never been able to do: a past session must show the households **as they stood then** — the name
they had that afternoon, the counts that were true then, the number they held, the card they
carried, the certificate date on file. Two of those eight values (**name**, **Erw. + Kinder**) are
not reconstructable at all, because editing a household overwrites them (US-16, FR-2), and three
more would have to be assembled out of three different histories. So all eight are **captured
together**: the hand-out becomes the **receipt** of who stood at the counter.

Requirements: `local_only/manually-start-ausgabe/refined-requirements.md` (E-4, E-5, E-7, E-8, E-9).
Full PRD: `tasks/prd-us-35-session-receipt.md`. Four stories.

**This batch has an expiry date, and it is the only one in the project that does.** Every session
ended before the freeze rule exists is lost to the detail view for good. It merges immediately after
US-34 and before DF are handed a build they run a real afternoon on.

What changes, in one line each:

- **`src/domain/distribution/handoutReceipt.ts`** — the nine captured columns and `receiptFor`,
  deriving the counts through `composition(members, at)` at the session's **end** instant.
- **`HandoutReceipt`** in the schema, one row per `DistributionRecord` (`recordId Int @unique`,
  `onDelete: Restrict`). **Price and paidCents are NOT copied** — both are already on the hand-out.
- **`freezeSession(sessionId, receipts)` / `thawSession(sessionId)`** on
  `DistributionRecordRepository`; ending takes the receipts in the **same transaction** as the
  ending, reopening gives them back in the same transaction as clearing `endedAt`.
- **ADR-021**, which reverses US-16's written „no history of past household compositions", and root
  `CLAUDE.md`'s „derive, don't store" list gains its **fourth** exception.

**Nothing in this batch is visible.** The receipts are written; the screen that reads them is US-37.

**The three things most likely to go wrong:**

- **The thaw is a DELETE, and ADR-010 forbids deleting.** It is the **third** deliberate exception
  beside `HouseholdMember` and `CertificateType`, and the schema comment has to say why: a receipt
  is not history, it is the freeze itself, re-taken whole by the next ending. A reopened session may
  have a hand-out **removed** (US-34, FR-14), and a receipt still pointing at it would make the store
  refuse that removal — thawing is what keeps the correction window open at all.
- **The group and the card number are NOT columns.** The group is `groupOf(customerNumber)` of the
  *captured* number (ADR-017) and the card number is `formatCardNumber(cardCustomerNumber,
  cardIndex)` — a `group` column here would be exactly the second recording US-31 removed. Capture
  the **card's own slot**, never the holder's current one (ADR-016).
- **Migrations are regenerated again** (the tenth time, ADR-009), so **both** hand-written partial
  unique indexes have to be re-added by hand: `Customer_customerNumber_onRegister_key` **and**
  `one_running_session` from US-34.3. `schema.test.ts` greps for both. `npm run db:reset` after, or
  the first symptom is the settings screen reporting that nothing is configured.

**Two deliberate acceptances that are not bugs.** A household moved to another number while the
session runs is captured under its **new** number and therefore its new group (E-5, J-1) — in a
RED-only session possibly as BLUE. And a child who turns 13 during the afternoon is counted by the
composition at the **end** instant, not by the price charged earlier — the same divergence
`Card.grownUpsAtIssue` already exposes. Comment them, do not argue with them.

**A household archived and its number given away is still the household that was served** (E-4): the
receipt is joined by `DistributionRecord.customerId`, the surrogate id, never the customer number.

**This is one piece of work in four parts** — 34 → 35 → 36 → 37. US-36 removes the week anchor, the
distribution weekday and `weekColour.ts`; US-37 is the session overview and detail view. A story in
this batch that finds itself deleting `weekColour.ts` has picked up US-36's work.

## 2026-09-20 — US-002 (US-35.2: the receipt table, written and thawed with the session)

- **Schema.** New `HandoutReceipt` model in `prisma/schema.prisma`: `recordId Int @unique` with a
  `DistributionRecord` relation (`onDelete: Restrict` stated out loud) plus exactly the nine captured
  columns of US-35.1 — no group, no formatted card number, no `priceCents`/`paidCents`. The model
  comment says the three things the code cannot: that it is a snapshot in `Card.grownUpsAtIssue`'s
  sense, that the group and the card number stay derived, and why these rows may be **deleted** where
  ADR-010 forbids it (the thaw is what keeps a reopened session correctable).
- **Migrations regenerated** (`20260919153410_init` → `20260920125124_init`), both hand-written
  indexes re-appended by hand, `npm run db:reset` after, and the reset database verified to carry
  `Customer_customerNumber_onRegister_key` and `one_running_session` by querying `sqlite_master`.
  `diff` against the old SQL shows only the new table and its unique index.
- **Port.** `freezeSession(sessionId, receipts)` and `thawSession(sessionId)` on
  `DistributionRecordRepository`, documented once there, with a new `FrozenHandout` type
  (`{ recordId, receipt }`) above the interface.
- **Adapter.** `freezeSession` is one `$transaction`: `deleteMany` the session's receipts, then
  `createMany`. `thawSession` is the `deleteMany` alone. Both reach the session through the relation
  filter `{ record: { sessionId } }`.
- **Fixtures.** `clearRegister` and `releaseNumbers` delete receipts before the records they point at;
  `demo-seed.ts` freezes every served afternoon before ending it (42 receipts for 42 hand-outs,
  verified by querying the seeded register). `prisma/seed.ts` is untouched — settings only.
- **Five integration tests** against a throwaway SQLite file: the round trip of all nine values, one
  receipt per hand-out and none for another afternoon, the re-take, the thaw leaving hand-outs
  untouched, and the store refusing to remove a hand-out its receipt still points at (P2003) then
  allowing it once thawed.
- Files: `prisma/schema.prisma`, `prisma/migrations/20260920125124_init/migration.sql`,
  `prisma/demo-seed.ts`, `src/application/ports.ts`,
  `src/infrastructure/prisma/distribution-record-repository.{ts,test.ts}`,
  `src/infrastructure/prisma/test-support.ts`, `tests/e2e/seeding.ts`, and the eight application test
  files whose fakes implement the port.
- Gates: lint, typecheck, `test:coverage` (63 files, 1429 tests, domain + application 100%), `build`,
  `format:check`, and **both** e2e engines (221 passed each) all green.

**Learnings for future iterations:**

- **Adding a method to `DistributionRecordRepository` is an eight-file test break**, and every one of
  them is a hand-written fake: `change-customer-number`, `maintain-customer`, `lookup-customer`,
  `customers`, `distribution-session`, `read-group-roster`, `record-attendance`,
  `correct-attendance`. The house stub is `Promise.reject(new Error("… has a suite of its own"))`,
  which is better than a no-op — a use case that starts calling the method fails loudly in the suites
  that have no business exercising it. Patch them with a script that inserts before the class's first
  `\n}\n`; `tsc` names the files but not the insertion point.
- **A transaction cannot span two ports in this codebase** — there is no unit of work, and
  `$transaction` appears only inside adapters. So „the receipts land in one transaction *with* the
  session's end" is implemented as **ordering plus idempotence**, not as one SQL transaction:
  `freezeSession` first (a failure leaves the session running), `end` second. `freezeSession`
  therefore begins with a `deleteMany` — the freeze is re-taken whole, which is also what heals a
  reopening whose thaw did not land. The alternative, stamping `endedAt` from the *record*
  repository, was refused: it would have hidden the one write everybody looks for in the session
  repository and left `sessions.end` dead.
- **A Prisma relation filter is how a child table is scoped by its grandparent.**
  `handoutReceipt.deleteMany({ where: { record: { sessionId } } })` needs no join and no id list; the
  same shape scopes `releaseNumbers`' delete by the customers it is releasing.
- **`omit: { id: true, recordId: true }` turns a round-trip test into one `toEqual`** against the
  domain value that was written — no field list to fall behind when a column is added. `findUniqueOrThrow`
  keeps it a single expression.
- **Assert the *code* of a refusal the database issues, and prove the assertion by breaking it.**
  A foreign key refusing a delete is `P2003`, not the `P2025` the adapter translates; `rejects.toSatisfy`
  reads it off `Prisma.PrismaClientKnownRequestError`. Flipping the code to `P9999` for one run is
  what separates a real assertion from one that passes on any rejection.
- **The demo seed cannot call `endDistributionSession`** — that use case reads `deps.clock.now()`,
  while every fixture instant is a historical `day.at`. So the seed freezes through the port directly
  and maps `RegisteredCustomer` → `ReceiptHousehold` by hand, which US-003 will do again in the use
  case. Two call sites, one deliberate: the alternative is a domain function taking a stored record,
  which is exactly what `ReceiptHousehold` exists to avoid.

## 2026-09-20 — US-003 (US-35.3: ending takes the receipts; reopening gives them back)

- **`endDistributionSession`** gains `customers: CustomerRepository` and, between summarising the
  afternoon and stamping it, builds one `FrozenHandout` per hand-out: `customers.findById` on the

  for a hand-out naming a household the register does not hold.
- **`reopenDistributionSession`** gains `records: DistributionRecordRepository` and calls
  `thawSession` **after** `sessions.reopen`, before the audit entry.
- **No call site changed**: `counterActionDeps` already carries `customers` and `records`, and every
  composition root is wider than each `Deps` interface (structural typing). `tsc` stayed green on
  `src/app/**` with no edit — the batch really is invisible.
- Tests (written first, nine red): `FakeCustomerRepository` and a `frozen` map plus a `freezeFails`
  flag on the record fake in `distribution-session.test.ts`, then the five named rules from the AC
  plus the card's own slot, the empty afternoon, the failed freeze and the unknown household.
- Files: `end-distribution-session.ts`, `reopen-distribution-session.ts`,
  `distribution-session.test.ts`. No `docs/` and no `prisma/` — US-004 owns both.
- Gates: lint, typecheck, `test:coverage` (63 files, 1439 tests, domain + application 100%), `build`,
  `format:check`, and **both** e2e engines (221 passed each) all green. The suite proved the wiring
  end to end without a new spec: each e2e register came out of the run holding **20 receipts**
  written by the real screen, action and adapter.

**Learnings for future iterations:**

- **Adding a dependency to a use case's `Deps` breaks nothing at the call sites**, and that is the
  design: every composition root in `src/app/**/deps.ts` is wider than each `Deps` interface, so a
  use case may start reading any port the root already holds without a single edit outside its own
  file and suite. Check the root before assuming a wide break — `counterActionDeps` holds all eight.
- **The end instant is only observable across Berlin midnight.** `composition` compares *calendar
  days*, so every instant of one afternoon gives the same counts and a test asserting "taken at the
  end, not at the hand-out" passes just as well against `session.startedAt`. The one fixture that
  separates them is an afternoon **ended after midnight** (`2026-01-08T23:30Z` = 00:30 Berlin) with a
  member whose 13th birthday is the next day. Without it the whole AC is untested.
- **A `Partial<T>` fixture builder hides a field that has to move with another.** `receipt()` defaults
  both `customerNumber` and `cardCustomerNumber` to 49, so the second household's expectation read
  `{ customerNumber: 50 }` and silently kept card slot 49 — a one-line diff at the end of a green
  implementation that looked like a bug in the use case. Where two fields are equal *by default and
  not by rule*, override both or let the builder derive one from the other.
- **Order between two stores is stated as a comment or it is not stated at all.** `freezeSession`
  before `end`, `thawSession` **after** `reopen`: the asymmetry is deliberate — each leaves the
  half-done state that the *next* act heals, since the freeze is re-taken whole. The port doc written
  in US-35.2 already anticipated „a reopening whose `thawSession` did not land", which is what
  settled the direction. Read the port before choosing an order.
- **A nullable port read inside the happy path needs a typed error, not a `??`.** `customers.findById`
  is `T | null` and the 100% branch gate reaches both arms only if the `null` is *thrown*, which also
  makes the refusal honest: a hand-out naming a household the register does not hold leaves the
  afternoon running rather than closing one that cannot be read back. `CustomerNotFound` already
  existed and `tierOf` already covers it, so no German string and no `notice-tier.ts` edit followed.
- **`Promise.all` over `handouts.map(async …)` is the house shape for N independent reads** (see
  `lookup-customer.ts`), preserves order for the assertion, and keeps a `throw` inside the callback
  working as a rejection. There is no `no-await-in-loop` rule, but the parallel form is what this
  codebase reads like.
- **Prove an invisible batch against the e2e registers, not with a new spec.** `data/e2e*.db` are
  ordinary SQLite files and a five-line `tsx` script against `PrismaClient` with
  `datasources.db.url = file:../data/e2e.db` counts what the suite just wrote. It has to live **inside
  the repo** (`@prisma/client` resolves nowhere else) and wrap its `await` in a function — the same
  two constraints the `local_only/` bullet above names.

**Learnings for future iterations:**

- **`npm run arc42:check` does not exist**, though three PRDs and this batch's AC name it. `package.json`
  has no such script; CI runs `python3 .claude/skills/arc42/scripts/arc42.py check` directly
  (`.github/workflows/ci.yml`). Run the script. Its clean output still lists the two long-standing
  `> **TODO:**` markers in chapter 07 — those are expected, not this story's.
- **Root `CLAUDE.md` and ADR-007 have never agreed on how many exceptions there are, and both are
  right.** The ADR's table counts `DistributionRecord.priceCents`; `CLAUDE.md`'s prose list never
  has. So one batch makes it „three → four" in one file and „four → five" in the other. Say which
  file a count belongs to before changing it, and state the discrepancy where a reader meets it
  (ADR-021's consequence does) rather than quietly aligning the two.
- **Never rewrap a markdown paragraph with a script that stops at the next blank line.** Two such
  rewraps swallowed the following list item into the paragraph above it (`CLAUDE.md`'s audit
  „Don't", chapter 08's `onDelete` bullet) and one turned a top-level bullet into a nested one by
  applying a two-space prefix to the `-` as well. `prettier --check` passes on all three, because
  every result is valid markdown — only reading `git diff` catches it. Re-wrap by hand, or bound the
  block by its own list marker.
- **The width sweep has to be re-run after each rewrap, not once at the end.** Fixing one 101-column
  line pushes words onto the next and creates the next violation, so the check is a loop:
  `git diff -U0 | python3 -c "…len(b) > 100…"` until it is silent. Exclude lines containing `](` —
  a long ADR link is unbreakable and Prettier accepts it.
- **A documentation story still has to ask what is true *today*.** The AC's German paragraph
  described the detail view US-37 builds, in a document DF actually hold; it was rewritten to
  describe what ending a session *does* („Was eine beendete Ausgabe festhält"), which is true now,
  is the one thing DF need in order to use the reopening sensibly, and reads identically once the
  screen lands. An AC written for a four-part piece of work can name a screen that is two batches
  away.
- **An ADR that reverses something gets a second home in chapter 09.** The „Decisions that were
  reversed" table is not covered by `arc42.py check` and no AC named it, but the chapter says in its
  own words why it exists — a reversal is the most useful row in a decision log. A batch whose PRD
  says „this reverses a written decision" owes that table a row.
- **Sweep the reversed claim's *phrasing* through `src/` too, not only `docs/` and `tasks/`.**
  `grep -rn "no history of past"` found the sentence copied into `ports.ts` and
  `customer-repository.ts` verbatim. The port was bounded (documented once, on the port); the
  adapter was left, since CLAUDE.md puts that comment's home on the port.
